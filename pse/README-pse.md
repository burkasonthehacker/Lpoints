# בורסת הנקודות (PSE) — הוראות התקנה והערות

קבצים חדשים/מעודכנים, לפי מבנה הריפו הקיים:

```
shared/firebase.js   ← עודכן: נוספו COLLECTIONS.pse, ADMIN_UIDS.pse, POINTS_SITES
pse/style.css
pse/logic.js
pse/index.html        (דף ציבורי, לפני התחברות)
pse/auth.html          (הרשמה / התחברות / שכחתי סיסמה)
pse/app.html            (האפליקציה: לוח מובילים, השקעה, תיק אישי, סטטיסטיקות)
pse/admin.html          (ניהול: משתמשים, התאמת שמות, המובילים)
```

**חשוב:** `shared/firebase.js` המצורף הוא הקובץ *המלא והמעודכן* — הוא כולל את כל מה שהיה בו קודם (liri, shanan) בתוספת הסעיפים של pse. פשוט מחליפים את הקובץ הישן בזה.

## חיבור לפיירבייס — האם צריך לעשות משהו?

**כמעט כלום.** `pse/*.html` מייבאים מ-`shared/firebase.js` בדיוק כמו liri/shanan/segev — כלומר הבורסה כבר מחוברת לאותו פרויקט פיירבייס קיים (`lpoints`), בלי צורך ביצירת פרויקט חדש. שני דברים בלבד דורשים פעולה ב-Firebase Console (לא בקוד):

1. **להפעיל Email/Password כשיטת התחברות** — כרגע liri/shanan/segev משתמשים רק ב-Google Sign-In, אבל הבורסה משתמשת בהרשמה עם מייל+סיסמה (כמו שביקשת באפיון). לכן: Firebase Console → Authentication → Sign-in method → Email/Password → Enable.
2. **חוקי Firestore** לקולקציות החדשות (`pse_users`, `pse_participants`, `pse_investments`) — ראו את הדוגמה למטה. שאר האתרים כנראה כתובים כרגע עם חוקים פתוחים או ספציפיים ל-liri_/shanan_/segev_ — צריך רק להוסיף בלוקים חדשים, לא לגעת בקיימים.

```
match /pse_users/{uid} {
  allow read: if request.auth.uid == uid || request.auth.uid == "<PSE_ADMIN_UID>";
  allow create: if request.auth.uid == uid;
  allow update: if request.auth.uid == "<PSE_ADMIN_UID>"
                || (request.auth.uid == uid && request.resource.data.status == resource.data.status);
}
match /pse_participants/{id} {
  allow read: if true;
  allow write: if request.auth.uid == "<PSE_ADMIN_UID>";
}
match /pse_investments/{id} {
  allow read: if request.auth != null;
  allow create, update: if request.auth.uid == resource.data.investorUid || request.auth.uid == request.resource.data.investorUid;
}
```

(נקודת התחלה סבירה — מומלץ לעבור עליה לפני production.)

Firestore עשוי גם לבקש **אינדקס מורכב** בפעם הראשונה שנטען גרף סטטיסטיקות (השאילתה משלבת `where("name",...)` עם `orderBy("timestamp",...)`). זה יופיע כשגיאה בקונסול עם קישור ליצירת האינדקס בלחיצה אחת — אין צורך להכין מראש.

## יצירת חשבון אדמין לבורסה (פעם אחת)

1. **פרסמו** את הקבצים (Vercel יעלה אוטומטית כמו תמיד).
2. **הירשמו** דרך `pse/auth.html` עם המייל שברצונכם שיהיה אדמין הבורסה — בדיוק כמו כל משתמש רגיל.
3. ב-Firebase Console → Authentication → Users, מצאו את המשתמש הזה והעתיקו את ה-**UID** שלו.
4. הדביקו את ה-UID בקובץ `shared/firebase.js`, במקום `REPLACE_WITH_PSE_ADMIN_UID` (שדה `ADMIN_UIDS.pse`), ופרסמו שוב.
5. **צעד ידני חד-פעמי:** ב-Firebase Console → Firestore Database → `pse_users` → מצאו את המסמך עם אותו UID → שנו את השדה `status` מ-`"pending"` ל-`"approved"` ידנית. (זה נדרש רק לאדמין הראשון — כי אין עוד אדמין שיאשר אותו; מכאן והלאה, האדמין מאשר משתמשים חדשים דרך `admin.html`.)
6. היכנסו עם אותו חשבון ל-`pse/admin.html` — עכשיו יש גישה מלאה.
7. **לפני שהלידרבורד יראה משהו הגיוני:** בטאב "ניהול משתתפים", עברו על ההתאמות המוצעות (או ערכו אותן) ולחצו "אישור כל ההתאמות" — זה יוצר את מסמכי `pse_participants` שמחברים בין השמות בכל האתרים. בלי זה הלידרבורד יהיה ריק, כי אין עדיין אף "משתתף" מוגדר.

## על ההתראות (עדכון)

כרגע **אין שליחת מייל בפועל** — זה בכוונה. כל התראה (הרשמה חדשה, אדם חדש שטרם שויך) פשוט מופיעה בתוך `admin.html`:
- טאב "ניהול משתמשים" מציג טבלת "משתמשים בהמתנה" בזמן אמת, עם **תג מספר** ליד שם הטאב בניווט אם יש ממתינים.
- טאב "ניהול משתתפים" מציג "אנשים חדשים שטרם שויכו", גם הוא עם תג מספר.

התשתית ל-EmailJS **נשארה בקוד** (`pse/auth.html`), אבל כבויה: `const EMAIL_NOTIFICATIONS_ENABLED = false;`. כשתרצו להפעיל שליחת מייל בעתיד — ממלאים את שלושת השדות (`EMAILJS_SERVICE_ID/TEMPLATE_ID/PUBLIC_KEY`, לפי ההוראות ששלחתי קודם) ומשנים את הדגל ל-`true`. שום קוד נוסף לא נדרש.


## מה מומש במלואו
- הרשמה/התחברות/שכחתי סיסמה מול Firebase Auth, עם אישור אדמין (סטטוס pending/approved/suspended/rejected).
- דף בית ציבורי עם Leaderboard חי, "תנודות אחרונות בשוק" (ממוזג משלושת האתרים), פייד-אאוט לשורה הרביעית שמוביל להתחברות.
- לוגיקת השקעה מלאה: יתרה פנויה/מושקעת, שינוי ערך ההשקעה יחסית לשינוי בנקודות המושקע (באחוזים), "הפסקת השקעה" שמחזירה את הערך הנוכחי למאגר הפנוי.
- דף סטטיסטיקות עם גרף גרירה-לזום (drag-to-zoom, במקום כפתורי טווח), טוגל "הפרדת סוגי נקודות", וקו נקודות מושקעות אם קיים.
- דף ניהול: אישור/דחיית משתמשים בהמתנה, השהיית חשבון עם הערה, כלי התאמת שמות אוטומטי (חפיפת מילים) עם אפשרות עריכה/ביטול לפני אישור, ודף "המובילים".
- עיצוב ייחודי ("רצפת מסחר" — פחם כהה, זהב-ברונזה, ירוק/אדום טיקר, פונט Mono למספרים) שלא חוזר על הפלטות של liri/shanan.

## מה פושט (ותצטרכו להשלים אם תרצו)
- **מחיקת חשבון Auth בפועל בעת "דחיית משתמש"** — דורש Admin SDK בצד שרת (Cloud Function). מה שממומש: הסטטוס משתנה ל-`rejected` והחשבון חסום מבחינת האפליקציה, אבל רשומת ה-Auth עצמה נשארת בפיירבייס עד שתמחקו אותה ידנית או תוסיפו Cloud Function.
- **שליחת מייל בפועל** — התשתית מוכנה וכבויה (ראו סעיף "על ההתראות" למעלה); כרגע הכול מוצג בתוך `admin.html` בזמן אמת.
- **התראה שדוחפת לאדמין (push) ברגע שמופיע אדם חדש** — כרגע זה מוצג כרשימה חיה בכל טעינה של `admin.html`, לא כהתראת push מיידית. זה ידרוש גם הוא Cloud Function עם onCreate trigger.
- שני הגרפים דורשים `chartjs-adapter-date-fns` (כלול ב-HTML, כמו באתרים האחרים).

בהצלחה עם הדיפלוי! אם תרצו שאשלים את חלק ה-Cloud Functions (מייל + התראות בזמן אמת), זה אפשרי בנפרד — רק תגידו.
